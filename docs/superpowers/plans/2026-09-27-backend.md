# Product Feedback Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver a tested FastAPI backend supporting reviewer submissions and evidence-backed PM analysis with durable MongoDB state and Hindsight memory.

**Architecture:** One API process and one Mongo-backed worker. Persist review/decision intent atomically with records; snapshot analysis inputs and fence worker writes with lease ownership. Isolate provider integrations behind typed adapters.

**Tech Stack:** Python, FastAPI, Pydantic, PyMongo, HTTPX, official Hindsight client, pytest.

**Spec:** ../specs/2026-09-27-backend-design.md — approved by user on 2026-09-27.

## Global Constraints

- Product identity is `parent_asin`, referring to products._id.
- All application routes use /api/v1; health routes expose no secrets.
- Integer rating 1–5; title up to 200 characters; nonblank review text up to 10,000 characters.
- Existing imported reviews have no source field; interpret those as amazon_2023.
- Batch C remains isolated from normal analysis memory. Baseline mode bypasses memory completely.
- Keep the existing 400,000,000-byte database capacity ceiling visible in operational documentation.
- No destructive collection operations. No raw text/ID rewriting, secrets in logs, frontend implementation or remote Git history changes.
- Demo bearer identities are server-configured; no public self-registration.
- No review edits/deletes until memory invalidation is implemented.
- Run tests against a dedicated database; application credentials do not implicitly select the application database for tests.
- Commit only task-owned paths after verification once a valid local Git base exists. The current unborn repository contains other work; do not create unrelated history or stage all files. If history cannot be reconciled safely, retain changes uncommitted and report it.

## Review Focus

1. A lost HTTP response followed by the same submission key must return one durable review, even across API processes (Task 2).
2. A worker completing after lease expiry must not publish results or overwrite its successor (Task 3).
3. A provider accepting retention before a network timeout must not duplicate memory on retry (Task 4).
4. A new live review or later PM decision must not leak into an older historical replay (Tasks 5–6).
5. A model quote can be verbatim but substantively misleading; distinguish provenance validation from semantic quality and test both (Tasks 5 and 8).

## Execution conventions and shared types

Paths below are relative to the repository root. Run Python commands from backend/ using its dedicated .venv. Use synchronous PyMongo repositories and FastAPI sync route functions; worker and provider adapters use synchronous calls with bounded timeouts. Do not reuse the data task's virtualenv. Validate supported package versions against official documentation before pinning dependencies.

Shared Pydantic types in app/domain.py: Principal(user_id, role), ReviewInput(title, text, rating, asin optional), Evidence(review_id, quote), FindingDraft(issue_type, theme, description, evidence), Scope(source, batch_id optional, available_through optional, evaluation=false), AnalysisInput(mode, scope), DecisionInput(kind, rationale, evidence_ids, available_through), JobClaim(collection, record_id, owner_token, expires_at), MemoryRecord(id, content, occurred_at, metadata), MemoryContext(text, record_ids). IDs are strings and datetimes are UTC-aware. Define ServiceError(code, status_code) in app/errors.py. Use bounded JSON objects for Mongo documents only inside repositories; routes serialize through explicit response models.

Default limits: page size 20/max 100; HTTP body 64 KiB; review submissions 10 per identity per minute; analysis maximum 1,500 reviews and chunks of at most 20 reviews/40,000 text characters; provider timeout 60 seconds; job lease 180 seconds with renewal; maximum 5 attempts; exponential retry delay min(300, 2**attempts) seconds. Reject a single record that cannot fit the configured model budget rather than silently truncating it. These are configuration defaults, not measured provider capacities.
